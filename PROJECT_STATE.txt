====================================================================
1. WHAT THE PROJECT IS
====================================================================
Real-time detection of AI voice-cloning on phone calls.

Pipeline: 4-second audio window -> frozen wav2vec2 XLS-R (300M) front-end
-> 1024-dim embedding (mean-pooled over time) -> small trained MLP head
(~300k params) -> risk score. Only the head is trained; the front-end is
frozen and never fine-tuned.

Headline metric is EER (equal error rate), NOT accuracy. Always reported as
"X% on <split name>", never as a bare number.

Repo layout that matters:
  extract_embeddings.py       audio -> embedding shards (the slow step)
  src/verify_protocol.py      dataset/protocol gate, run before anything
  src/train.py                trains the MLP head
  src/eval.py                 produces the EER number
  src/score_file.py           score_file(wav) -> list[float]
  src/make_codec.py           codec-robustness degradation
  make_codec.py               second copy at repo root
  demo/                       Streamlit UI (10 files)
  _anubhav_sample/            60-file mini dataset, real --data-root layout

3. THE BLOCKING BUG - fp16 PRODUCES 100% NaN
====================================================================
extract_embeddings.py:200 calls model.half() whenever the device is CUDA.
On this machine that yields embeddings that are entirely NaN.

Same file, same GPU, three paths:
    cuda/fp16    nan=1024/1024   range=n/a
    cuda/fp32    nan=   0/1024   range=-0.9028..0.8091
    cpu /fp32    nan=   0/1024   range=-0.9028..0.8091

CUDA fp32 matches CPU bit-for-bit, so the model, the audio and the GPU are
all fine. The cause is the blanket fp16 cast: wav2vec2's conv feature encoder
overflows fp16's 65504 ceiling. Usual fix is torch.autocast instead of
.half(), which keeps norm layers in fp32.

THE FAILURE IS SILENT. A 50-file smoke run reported:
    [eval] DONE. succeeded=50  skipped(bad)=0  already_cached=0  total=50
    [eval] first written shard shape = (50, 1024)  (expect (*, 1024))
while every one of the 51200 values was NaN. The script's self-check
validates shape only, never finiteness. This is how dead data gets cached as
"done" and why the bug survived this long.

NOT YET FIXED. extract_embeddings.py is Yugal's lane and his scoring step
depends on its exact output format, so the fix is his call. Two changes are
wanted: the .half() precision fix, and a finiteness assert so this can never
again pass as success.
