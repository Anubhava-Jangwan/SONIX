02Scope

In. Browser microphone capture, sample-rate normalisation, the sliding window, the silence gate, consent gating on real audio, per-window telemetry, and the live chart.

Out. Training anything, the wav2vec2 embedding step, threshold calibration, Asterisk/SIP. Those sit in Lanes 1–2, or in phase 4 below.

The rule this lane is built around

The dashboard shows no risk band while no trained head is loaded. A mock number rendered as a verdict is the single thing most likely to lose the jury Q&A, so the gate is enforced server-side through a scoring_available flag — not by remembering to hide it.

03How live audio connects

Capture happens in the browser and arrives as binary frames on the same WebSocket the dashboard already uses. Nothing native is installed on Windows, and it is the path the deck already claims.

Browser
getUserMedia → AudioWorklet @ 16 kHz Float32 frames converted to little-endian int16 PCM, sent as WebSocket binary frames.
Transport
ws://localhost:8000/ws TEXT start_mic_call creates the session and returns a pairing code. BINARY frames carry the audio.
Normalise
pcm16 → float32 → resample to 16 kHz Browsers hand over 48 kHz, Asterisk 8 kHz. wav2vec2 was trained at 16 kHz and is sensitive to anything else.
Consent
Session.push_audio() drops everything until approved Not a UI convention — the state machine refuses the audio, and the audit trail records the refusal.
Window
4.0 s window, 0.5 s hop 87.5% overlap. The first window waits until it is genuinely full — a half-silent window is exactly the input that produces a false “fake”.
Silence gate
25 ms frames, RMS + zero-crossing, ≥20% speech to pass Every window is logged whether it passes or not, which is what makes the gate visible on the chart instead of merely claimed.
Embed
Still a stub — returns random noise No wav2vec2 exists anywhere in realtime/. This is phase 4, and it is on the critical path.
Score
Batches ≤8 windows across calls every 0.5 s Mock scorer today; head.pt via --ckpt when it arrives.

One constraint that will bite on stage

getUserMedia requires a secure context. http://localhost counts; a LAN IP does not. Demo from the machine running the server, or the browser silently refuses the microphone.

04The chart

Two charts, deliberately not sharing a pair of axes. A risk probability and an audio level are different measures, and putting them on one y-axis would misrepresent both.

Risk timeline — hidden until a real head is loaded

P(AI voice) against seconds into the call on a 0–100% axis, with the Green / Amber / Red bands shaded behind the line and the two thresholds drawn as labelled dotted rules. One series, so the line needs no legend. Band colours always ship with a text label, never colour alone.

Audio path — always visible

Speech ratio per window, with windows the silence gate dropped marked as grey ×. This is the chart that keeps the demo honest while scoring is off: it shows capture, windowing and the gate genuinely working on live microphone audio, and there is nothing in it to fake.

Thresholds are provisional

Amber ≥ 35%, Red ≥ 65%, carried over from the clean benchmark and captioned as provisional on screen. Lane 1 owns recalibration on real recordings; when it lands, change AMBER_AT and RED_AT in live_ui.py.

fp16 is not a theoretical problem

The cached G.711 eval embeddings in this clone are 100% NaN — all 350 rows across all four shards. The clean set is 2.5% NaN, 550 rows of 21,794. Any EER computed from the G.711 set today is meaningless, and it would land near 40%, which reads like a label bug rather than what it is.

07Running it

pip install -r requirements.txt

# terminal 1 — server
python -m realtime.server --mock --ws-port 8000 --mode webrtc

# terminal 2 — dashboard
streamlit run realtime/live_ui.py

# browser tab — capture (Chrome/Edge, must be localhost)
http://localhost:8000/mic

Press Start capture, allow the microphone, read the six-digit pairing code off the capture page, approve it in the dashboard's Live Calls tab. The audio-path chart starts moving about four seconds later — the first window has to fill.

Once head.pt exists:

python -m realtime.server --ckpt outputs/models/head.pt --ws-port 8000 --mode webrtc

That flips scoring_available to true and reveals the risk timeline. Nothing in the dashboard needs to change.

08Verified

End-to-end against a running server: 14 seconds of synthetic audio sent at 48 kHz with a five-second silent stretch in the middle.

  • Audio sent before approval → 0 windows emitted. The consent gate holds.
  • 48 kHz → 16 kHz: 14.0 s in, 14.0 s buffered.
  • 21 windows emitted from 14 s at 4.0 s / 0.5 s — arithmetically correct.
  • Silence gate dropped 5 of 21.
  • scoring_available: false throughout, so the risk band stayed hidden.
  • All 12 existing tests in realtime/tests/ still pass.

None of this is covered by the test suite yet. Phase 4 should add cases for the ring buffer's window arithmetic and the VAD boundary — the two places a silent regression would be expensive.
